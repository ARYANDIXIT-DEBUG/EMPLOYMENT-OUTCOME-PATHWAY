| Weights for documented survey estimates | **DOCUMENTED** | README §B, “Use of Sub-sample wise weights (Quarter wise multipliers)”: “Final Weight = MULT /100” for quarter/sub-sample estimates; “Final weight = MULT /200” where NSS and NSC differ for combined estimates. Do not weight pathway prevalence unless MoSPI confirms the intended longitudinal estimand and applicable weight. |
| CWS broad employment-status groups | **DOCUMENTED** | Instruction Manual Vol. I, §3.6.14, printed pp. C-50–C-52 (PDF pp. 104–106): “employed (any of codes 11-72), unemployed (any of codes 81 or 82) and out of labour force (any of codes 91-98).” The instructions further state that an employed code on any day takes precedence; 81/82 applies only if there is no 11–72 code. | The broad CWS groups are documented. The project config currently lists 98 under `unknown_codes`; this conflicts with the manual’s broad range and needs authoritative reconciliation against the precise CWS code table before mapping is treated as validated. Missing CWS observations must remain missing; the cited rule does not convert missing data to unemployment. |

## Written clarification the user must obtain

Obtain written answers from the MoSPI data custodian or an authority authorized to interpret the Catalogue 213 rider before opening any affected real-data analysis gate:

1. Is `b4q12` permitted solely to select a trainee cohort when the analyzed outcome is employment/CWS? Does this count as specifically studying a non-employment variable under the rider?
2. Is profiling employment pathways by age, gender, household type, religion, social group, or household expenditure permitted? Specify allowed variables, output restrictions, and any minimum-cell or disclosure rules.
3. Are the provided multipliers valid for person-level records linked across revisits or for trajectory/pathway prevalence? If yes, provide the target estimand and exact weight/formula to use.
4. Does this release define a person-level nonresponse, attrition, or “lost” code? If so, identify the variable and code values, and explain how they differ from household casualty, temporary absence, and an absent person record. If none exists, request that this be stated explicitly.
5. Confirm the approved longitudinal person-linking key against the README person-record key and the quarter/panel visit schedule. Specifically clarify whether quarter and visit are only time fields for matching repeat records, whether sector belongs in the persistent link key, and how sample-design fields are expected to behave across visits.
6. Is there an official tolerance or adjudication rule for age differences across linked visits? If not, request written confirmation that no threshold is specified.
7. Reconcile the project’s treatment of CWS code 98 with the manual’s stated out-of-labour-force range 91–98 and identify the authoritative code label/classification for this release.
